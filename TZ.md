# Техническое задание (ТЗ)

**Проект**: AI-чат-бот для Саморегулируемой организации «Нижегородское объединение строительных организаций» (СРО НОСО)

**Версия документа**: 1.0
**Дата**: 19 января 2026 г.
**Автор**: Команда разработки SRO NOSO

## 1. Введение

### 1.1. Цель проекта

Создание интеллектуального Telegram-чат-бота для автоматизации консультаций и информационной поддержки членов Саморегулируемой организации «Нижегородское объединение строительных организаций» (СРО НОСО).

### 1.2. Задачи проекта

- Автоматизация рутинных консультаций по законодательству и внутренним регламентам СРО
- Предоставление круглосуточного доступа к документам и информации
- Улучшение качества обслуживания членов СРО
- Снижение нагрузки на специалистов СРО

### 1.3. Целевая аудитория

- Члены СРО НОСО (строительные организации и индивидуальные предприниматели)
- Специалисты СРО (консультанты, юристы, технические эксперты)
- Администраторы и руководители СРО

## 2. Функциональные требования

### 2.1. Основные функции бота

#### 2.1.1. Команда /start
- **Описание**: Приветствие пользователя и инициализация профиля
- **Функциональность**:
  - Регистрация нового пользователя в системе
  - Отображение главного меню
  - Проверка членства в СРО (опционально)

#### 2.1.2. Команда /help
- **Описание**: Справка по использованию бота
- **Функциональность**:
  - Список доступных команд
  - Краткое описание каждой команды
  - Контакты для получения дополнительной помощи

#### 2.1.3. Команда /profile
- **Описание**: Управление профилем пользователя
- **Функциональность**:
  - Просмотр текущих данных профиля
  - Редактирование информации об организации
  - Отображение статуса членства в СРО
  - История взаимодействий с ботом

#### 2.1.4. Команда /consultation
- **Описание**: Получение консультаций с использованием ИИ
- **Функциональность**:
  - Прием вопросов на естественном языке
  - Анализ релевантных документов
  - Генерация ответов на основе базы знаний СРО
  - Сохранение истории консультаций

#### 2.1.5. Команда /documents
- **Описание**: Работа с документами СРО
- **Функциональность**:
  - Просмотр списка доступных документов
  - Поиск документов по категориям
  - Скачивание документов
  - Краткие конспекты документов

#### 2.1.6. Команда /membership
- **Описание**: Информация о членстве в СРО
- **Функциональность**:
  - Проверка статуса членства по ИНН или названию организации
  - Интеграция с реестрами НОСТРОЙ и НОПРИЗ
  - Информация о требованиях к членству
  - Справка по взносам и платежам

### 2.2. AI-функциональность

#### 2.2.1. Система RAG (Retrieval-Augmented Generation)
- **Описание**: Интеллектуальный поиск и генерация ответов
- **Требования**:
  - Обработка документов PDF и DOCX
  - Векторный поиск по семантическому сходству
  - Генерация контекстно-зависимых ответов
  - Поддержка русского языка

#### 2.2.2. Интеграция с DeepSeek API
- **Модель**: DeepSeek Chat (или аналогичная)
- **Функциональность**:
  - Генерация ответов на основе промптов
  - Обработка контекста из документов
  - Управление температурой и максимальной длиной ответа

### 2.3. Административные функции

#### 2.3.1. Система модерации
- **Описание**: Управление контентом и пользователями
- **Функциональность**:
  - Мониторинг использования бота
  - Управление списком разрешенных документов
  - Статистика использования

## 3. Нефункциональные требования

### 3.1. Производительность

- **Время отклика**: Не более 3 секунд на типичный запрос
- **Пропускная способность**: Не менее 100 одновременных пользователей
- **Доступность**: 99% uptime (за исключением планового обслуживания)

### 3.2. Безопасность

- **Аутентификация**: JWT-токены для API
- **Шифрование**: HTTPS для всех внешних соединений
- **Валидация**: Проверка всех входных данных
- **Логирование**: Аудит всех действий пользователей

### 3.3. Масштабируемость

- **Архитектура**: Микросервисная (опционально для будущих версий)
- **База данных**: PostgreSQL с поддержкой шардинга
- **Кеширование**: Redis для сессий и часто запрашиваемых данных

### 3.4. Удобство использования

- **Интерфейс**: Интуитивно понятный Telegram-интерфейс
- **Язык**: Русский язык для всех сообщений
- **Обработка ошибок**: Понятные сообщения при ошибках

## 4. Архитектура системы

### 4.1. Компоненты системы

#### 4.1.1. Backend (Python/FastAPI)
- **Язык**: Python 3.11+
- **Фреймворк**: FastAPI + Aiogram 3
- **База данных**: PostgreSQL 15+
- **Кеширование**: Redis 7+

#### 4.1.2. AI-компоненты
- **LLM**: DeepSeek API
- **Векторный поиск**: FAISS
- **Обработка документов**: PyPDF2, python-docx

#### 4.1.3. Мониторинг
- **Метрики**: Prometheus
- **Визуализация**: Grafana (опционально)
- **Логирование**: Structlog + JSON

### 4.2. Структура данных

#### 4.2.1. Пользователи
```sql
- telegram_id (bigint, PK)
- username (varchar)
- first_name (varchar)
- last_name (varchar)
- organization_name (varchar)
- is_member (boolean)
- registration_date (timestamp)
```

#### 4.2.2. Сообщения
```sql
- id (serial, PK)
- user_id (bigint, FK)
- message_text (text)
- message_type (varchar)
- timestamp (timestamp)
- ai_response (text)
```

#### 4.2.3. Документы
```sql
- id (serial, PK)
- filename (varchar)
- title (varchar)
- category (varchar)
- upload_date (timestamp)
- vector_index_path (varchar)
```
