# Политика безопасности

## Поддерживаемые версии

Мы серьезно относимся к безопасности нашего проекта и будем выпускать исправления для следующих версий:

| Версия | Поддерживается          |
|--------|-------------------------|
| 1.0.x  | :white_check_mark: Да   |
| < 1.0  | :x: Нет                 |

## Сообщение об уязвимостях

Если вы обнаружили уязвимость в безопасности, **НЕ** создавайте публичный issue. Вместо этого, пожалуйста, сообщите о ней конфиденциально.

### Как сообщить об уязвимости

1. **Отправьте email** на адрес: security@sro-noso.ru
2. **Или используйте Telegram**: @sro_noso_security
3. **Тема письма**: "Security Vulnerability Report - SRO NOSO Chat-Bot"

### Что указывать в сообщении

Пожалуйста, предоставьте подробную информацию о уязвимости:

- **Описание проблемы**: Подробное объяснение уязвимости
- **Шаги воспроизведения**: Как воспроизвести проблему
- **Потенциальное воздействие**: Что может произойти при эксплуатации
- **Предлагаемое решение**: Если у вас есть идеи по исправлению (опционально)
- **Контактная информация**: Как с вами связаться для уточнения деталей

### Наша ответственность

- **Конфиденциальность**: Мы будем держать вашу информацию в строгой конфиденциальности
- **Своевременность**: Мы рассмотрим ваше сообщение в течение 48 часов
- **Обратная связь**: Мы будем держать вас в курсе прогресса исправления
- **Признание**: После исправления мы признаем ваш вклад (если вы этого хотите)

## Процесс исправления уязвимостей

1. **Получение отчета** - Мы получаем и анализируем ваше сообщение
2. **Валидация** - Проверяем уязвимость на наших системах
3. **Приоритизация** - Определяем критичность и сроки исправления
4. **Исправление** - Разрабатываем и тестируем исправление
5. **Релиз** - Выпускаем исправление с соответствующим патчем
6. **Объявление** - Публикуем информацию об исправлении

## Временные рамки

- **Критические уязвимости** (CVSS 9.0+): Исправление в течение 7 дней
- **Высокий приоритет** (CVSS 7.0-8.9): Исправление в течение 30 дней
- **Средний приоритет** (CVSS 4.0-6.9): Исправление в течение 90 дней
- **Низкий приоритет** (CVSS < 4.0): Исправление в плановом порядке

## Рекомендации по безопасности

### Для пользователей

1. **Регулярно обновляйте** бота до последней версии
2. **Используйте сильные пароли** для административных аккаунтов
3. **Мониторьте логи** на подозрительную активность
4. **Ограничивайте доступ** к базе данных только необходимыми правами

### Для разработчиков

1. **Всегда используйте** подготовленные запросы для работы с БД
2. **Валидируйте входные данные** на всех уровнях
3. **Шифруйте чувствительные данные** в транзите и хранении
4. **Регулярно обновляйте** зависимости проекта
5. **Проводите code review** для всех изменений

### Конфигурация безопасности

Рекомендуемая конфигурация для продакшена:

```bash
# Секретные ключи
JWT_SECRET_KEY=your-very-secure-jwt-secret-here
SECRET_KEY=your-very-secure-secret-key-here

# Настройки БД
POSTGRES_USER=sro_bot_user
POSTGRES_PASSWORD=strong-password-here

# API ключи
DEEPSEEK_API_KEY=your-deepseek-api-key
TELEGRAM_BOT_TOKEN=your-bot-token

# Режим работы
ENVIRONMENT=production
DEBUG=false
```

## Безопасность API

### DeepSeek API
- Все запросы к DeepSeek API шифруются по HTTPS
- API ключи хранятся в защищенных переменных окружения
- Реализован rate limiting для предотвращения злоупотреблений

### Telegram Bot API
- Используется официальный Bot API Telegram
- Вебхуки защищены секретным токеном
- Проверка подлинности входящих обновлений

### База данных
- Использование PostgreSQL с ролевым доступом
- Шифрование чувствительных данных
- Регулярные бэкапы с шифрованием
