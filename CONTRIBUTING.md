# Внесение вклада в проект SRO NOSO Chat-Bot

Спасибо за интерес к проекту чат-бота для Саморегулируемой организации «Нижегородское объединение строительных организаций» (СРО НОСО)!

## Как внести вклад

### 1. Подготовка среды разработки

```bash
# Клонирование репозитория
git clone https://github.com/yourusername/sro-noso-chatbot.git
cd sro-noso-chatbot

# Создание виртуального окружения
python -m venv venv
source venv/bin/activate  # или venv\Scripts\activate на Windows

# Установка зависимостей
pip install -e ".[dev,test]"

# Настройка pre-commit хуков
pre-commit install

# Копирование файла с переменными окружения
cp .env.example .env
# Отредактируйте .env файл с вашими ключами API
```

### 2. Структура проекта

```
sro-noso-chatbot/
├── app/                    # Основной код приложения
│   ├── ai_integration/     # Интеграция с ИИ (DeepSeek)
│   ├── bot/               # Telegram бот
│   ├── database/          # Работа с базой данных
│   ├── models/            # SQLAlchemy модели
│   ├── services/          # Бизнес-логика
│   ├── monitoring/        # Мониторинг и метрики
│   └── utils/             # Вспомогательные утилиты
├── config/                # Конфигурация
├── data/                  # Данные (документы, векторные индексы)
├── scripts/               # Скрипты для обслуживания
├── tests/                 # Тесты
└── docker/                # Docker файлы
```

### 3. Стиль кода

Проект использует следующие инструменты для поддержания качества кода:

- **Black** - форматирование кода
- **isort** - сортировка импортов
- **flake8** - проверка стиля
- **mypy** - статическая типизация
- **pre-commit** - автоматическая проверка перед коммитом

### 4. Процесс разработки

1. Создайте issue для новой фичи или бага
2. Создайте ветку от `main`: `git checkout -b feature/your-feature-name`
3. Внесите изменения, следуя стилю кода
4. Напишите тесты для новых функций
5. Запустите тесты: `pytest`
6. Создайте pull request с подробным описанием изменений

### 5. Тестирование

```bash
# Запуск всех тестов
pytest

# Запуск с покрытием
pytest --cov=app --cov-report=html

# Запуск конкретного теста
pytest tests/test_specific_feature.py
```

### 6. Работа с базой данных

```bash
# Создание новой миграции
alembic revision -m "Описание изменений"

# Применение миграций
alembic upgrade head

# Откат миграции
alembic downgrade -1
```

### 7. Развертывание

Проект поддерживает развертывание через Docker:

```bash
# Сборка образа
docker build -t sro-noso-chatbot .

# Запуск через docker-compose
docker-compose up -d
```

## Правила коммитов

- Используйте понятные сообщения коммитов на русском или английском
- Начинайте с глагола: "Добавить", "Исправить", "Обновить"
- Описывайте что и зачем изменено

Примеры:
- ✅ `Добавить валидацию данных пользователя`
- ✅ `Исправить ошибку в обработке документов`
- ❌ `fix`
- ❌ `update`

## Типы изменений

- **feat**: новая функциональность
- **fix**: исправление багов
- **docs**: изменения документации
- **style**: форматирование кода
- **refactor**: рефакторинг кода
- **test**: добавление/изменение тестов
- **chore**: изменения в инфраструктуре

## Сообщение о багах

При создании issue с багом укажите:
- Шаги для воспроизведения
- Ожидаемое поведение
- Фактическое поведение
- Логи ошибок
- Версию Python и ОС

## Запросы на новые функции

Для новых функций создавайте issue с меткой `enhancement` и описанием:
- Зачем нужна эта функция
- Как она должна работать
- Примеры использования
